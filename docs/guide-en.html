1. What it is and why it exists

Your Flutter conventions live in two places that cannot talk to each other: a prose document, and roughly 900 Dart files that nothing can query.

Every new Claude Code session re-derives your architecture from CLAUDE.md — from a description of the rules rather than from the code that already follows them. And every correction you make is lost when that session ends.

flutter-agent closes both gaps:

  • It indexes your real code. Ask "how do we do pagination" and it answers with your PaginatedResult, not a generic Flutter tutorial.
  • It enforces your rules statically. Twelve checks that read the source and decide — no model involved, so they are fast, free and deterministic.
  • It scaffolds in your style. A generated feature is modelled on bilhikma/features/archive, the cleanest instance of the layout in your corpus.
  • It remembers corrections. When you correct Claude, that correction is recorded, indexed, and recalled in later sessions.

What it is not

It is not a code generator that replaces thinking, and it does not decide whether code compiles — flutter analyze remains the only authority on that, and the agent shells out to it rather than approximating it.

The architecture it encodes

Every feature has exactly two halves, and there is no domain/, entities/, use_cases/ or repo_interface/:

lib/features/<feature>/
  data/
    data_source/   # the ONLY place that talks to a backend or storage
    models/        # fromJson / toJson
    repos/         # delegation, nothing else
  presentation/
    cubit/         # every decision the screen makes
    refactor/      # body sections pulled out of a screen
    screens/       # 30-70 lines: create the cubit, render the body
    widgets/       # small dumb components

2. How it works

your Dart projects ──┐
knowledge/           ├─► parser ─► chunker ─► GPU embeddings ─► FAISS ─┬─► MCP ─► Claude Code
 (rules, patterns,   │                                                 └─► CLI
  lessons)  ─────────┘

Step by step

  1. Parse. A hand-written Dart scanner finds declarations, members, imports and string literals. It is not a Dart compiler and does not try to be — its job is to find boundaries and metadata.
  2. Chunk. One chunk per top-level declaration. A 600-line Cubit is split at member boundaries, and every part repeats the class header so a chunk from the middle still knows what it belongs to.
  3. Tag. Each chunk records its project, feature, layer, symbol and line range. That is what makes --layer data_source possible.
  4. Embed. Computed locally on your RTX 4050 with all-MiniLM-L6-v2 (~90 MB). The full corpus takes about 24 seconds.
  5. Store. FAISS for the vectors, SQLite for the metadata, keyed so the two can never drift apart.
  6. Serve. Through MCP to Claude Code, and through the CLI to you.

Indexing is incremental. Only files whose SHA-256 changed are re-embedded. Re-indexing after editing one Cubit costs one embedding call, not nine hundred — typically under two seconds.

Why the lexing matters

Counting braces over raw text breaks the moment a brace appears inside a comment, a string, or a ${...} interpolation. Everything therefore runs over a masked copy of the source in which comments and string literals are blanked out, position for position. This handles nested block comments, raw and triple-quoted strings, and the legal-but-awkward '${map['key']}'.

Braces are also only counted outside parentheses, because Dart spells named parameters ({required this.repo}) — counting those as a body brace cuts every such constructor in half.

Validated on your corpus: 885 files, 1,332 declarations, 8,137 members, zero crashes.

flutter-agent index

The index is global, not per project — deliberately. A pattern should be findable wherever you first wrote it, so searching while working on hikmaapp still surfaces the right answer from bilhikma.

What gets indexed

Every .dart file under the project, except generated code (*.g.dart, *.freezed.dart, *.gr.dart, *.config.dart, *.mocks.dart), tests, and the platform folders (android/, ios/, web/, …). Generated code carries no architectural signal and would swamp retrieval.

Per-project tuning is optional. Drop a .flutter-agent.json in a project root to override include, exclude, max_chunk_chars or the embedding model for that project only.

5. Using it inside Claude Code

This is the main way to use it. You do not call the tools yourself — you ask normally, and Claude reaches for them.

What you sayWhat Claude does
"Add a notifications feature to bilhikma"flutter_pattern → flutter_component → flutter_scaffold
"Review what I wrote in features/profile"flutter_check on that folder
"This body file is too long, split it"flutter_refactor_plan, then performs the split
"How do we handle errors here?"flutter_pattern("error handling")
"Is there a widget for empty states?"flutter_component()

You can also name a tool explicitly: "use flutter_search to find how we do pagination".

The ten tools

ToolWhat it answers
flutter_patternHow this codebase does X — the rule, a golden example, and past corrections. Call before implementing.
flutter_searchSemantic search over the Dart corpus, filterable by layer, feature, project or kind
flutter_componentWhat the shared package exports; with a name, its definition plus real call sites
flutter_checkArchitecture-rule violations for a file, feature or project
flutter_refactor_planWhat to extract from an oversized file, largest method first, plus a precedent
flutter_scaffoldA complete feature folder plus localization keys. Dry run by default
flutter_lesson_addRecord a correction so it is recalled later
flutter_lessonsRecall corrections by topic
flutter_reindexRe-scan sources after a lot of editing
flutter_statusIndex health, registered sources, device, counts

Why this makes Claude cheaper as well as better. Without the agent, answering "how do we do pagination here" means reading several large Dart files into context. flutter_pattern returns a few hundred tokens of exactly the relevant declarations instead.

Step 4 — the one thing left to do

The data source ships a working stub with the error contract already in place. Replace the body of fetchItems with the real call:

Future<List<NotificationsModel>> fetchItems() async {
  try {
    // replace this with the real backend call
    const List<Map<String, dynamic>> raw = <Map<String, dynamic>>[];
    return raw.map(NotificationsModel.fromJson).toList(growable: false);
  } on NotificationsException {
    rethrow;
  } catch (error) {
    throw NotificationsException(mapError(error));
  }
}

Then register it in the service locator — note registerFactory for the cubit:

getIt
  ..registerFactory(() => NotificationsCubit(repo: getIt()))
  ..registerLazySingleton(() => NotificationsRepo(dataSource: getIt()))
  ..registerLazySingleton(NotificationsDataSource.new);

Cubits are always registerFactory. A singleton cubit keeps the previous screen's state and emits after close() — the single most common cause of "state from the last time I opened this screen".

The feature name is normalised, so LessonDetail, lesson-detail and lesson detail all produce lesson_detail / LessonDetail / lessonDetail in the right places.

8. The architecture rules

Twelve static checks. No model is involved in any of them — each is a property of the source that can be decided by reading it.

All pattern matching runs against the masked copy of the file, so a rule can never fire on a word inside a comment or a string literal.

IDRuleSeverity
R1Folder layout — no domain/, entities/, use_cases/, repo_interface/, repo_impl/, presentations/; canonical folder nameserror / warning
R2No package:<own_project>/… self-imports inside lib/error
R3Files stay within their layer's line budgeterror / warning
R4Screens hold no _build… layout methodserror
R5Presentation never calls Firestore, Supabase, SharedPreferences, Dio, http, Hive or secure storageerror
R6Cubits never touch BuildContext, Navigator, ScaffoldMessenger, dialogs or bottom sheetserror
R7UI text goes through LangKeys — never 'raw_key'.tr() or a hardcoded stringerror / warning
R8LangKeys, ar.json and en.json describe the same key seterror / warning
R9Repos delegate without control flowwarning
R10No Expanded/Flexible inside an unconstrained scrollable (heuristic)warning
R11Models define at least one of fromJson / toJsonwarning
R12Features carry the canonical subfolders (grouping folders are skipped)warning

Line budgets (R3)

LayerTargetCeiling
Screen70150
Refactor body / widget120150
Repo120250
Model200400
Cubit / data source400900

A cubit has a generous ceiling because behaviour is genuinely its job. A screen has a tight one because a screen that grew past it has absorbed work belonging to a cubit or a widget.

R6 in practice — the most important rule

// wrong — the cubit reaches into the widget tree
Future<void> save() async {
  await repo.save();
  Navigator.of(context).pop();
  ScaffoldMessenger.of(context).showSnackBar(...);
}

// right — the cubit emits, the screen listens
Future<void> save() async {
  await repo.save();
  if (isClosed) return;
  emit(state.copyWith(status: ProfileStatus.saved));
}

A cubit outlives any single widget and may emit after that widget is gone. Holding a context produces "used a BuildContext across an async gap" at best, and a crash at worst.

if (isClosed) return; after every await, before every emit. The user can leave the screen mid-request, and emitting on a closed cubit throws. This appears in every cubit in your corpus — it is not optional style.

R7 in practice

Text('saved_items'.tr())   // raw key — nothing stops a typo
Text('Saved items')       // hardcoded, never translated
Text(LangKeys.savedItems.tr())

The constant is not decoration: 'saved_itmes'.tr() compiles, ships, and renders the key itself to the user. LangKeys.savedItmes does not compile.

Interpolated and non-linguistic strings are correctly ignored — Text('$count'), Text('-'), Text('2x').

9. The knowledge base

knowledge/ is plain Markdown you can read, edit and commit. Run flutter-agent index after changing it.

FolderKindContents
rules/ruleWhy a constraint exists, with real before/after
patterns/patternGolden examples lifted from the corpus, with commentary
lessons/lessons.jsonllessonAppend-only corrections captured from sessions

What ships today

Rule cards: layering, localization, errors, file-size.
Pattern cards: cubit-and-state, screen-and-body, data-source-and-model, pagination, dependency-injection.

This is the part you grow. Topics without a card fall back to a weaker match. The fastest way to add one is to ask Claude: "write a knowledge pattern card for image upload based on how skygate does it" — it reads the corpus, writes the Markdown, and you re-index.

Writing a good card

  • Show real code from the corpus, not invented examples.
  • Explain the decision, not the syntax. "Why clearError exists" is useful; "copyWith copies the state" is not.
  • Include the wrong version. Retrieval is much better at matching a mistake someone is about to make when the mistake is written down.
  • One topic per file, with ## headings — the chunker splits on those.

10. The learning loop

This is what makes it an agent that improves rather than a search index that stays still.

When to record a lesson

  1. You correct Claude's Flutter code. Record what was written, what it should have been, and why.
  2. flutter analyze rejects generated code. Record the error and the fix.
  3. flutter_check finds a violation that then gets fixed. Pass the --rule id so the lesson surfaces next to that rule.
  4. A convention is discovered that no rule encodes. If it recurs, promote it to a rules/ card.

Recording one

flutter-agent lesson "cubit registered as singleton" `
  "getIt..registerFactory(() => ArchiveCubit(repo: getIt()));" `
  --wrong "getIt..registerLazySingleton(() => ArchiveCubit(repo: getIt()));" `
  --why "A singleton cubit keeps the previous screen's state and emits after close()." `
  --tag di --tag cubit --layer cubit --rule R6

Recorded lesson 9e014a3bcf6a and indexed: cubit registered as singleton

In Claude Code you do not type this — you say "remember that" after a correction, and Claude calls flutter_lesson_add.

Recalling

flutter-agent lessons "how do I register a cubit in get_it"

Lessons also appear automatically inside flutter-agent pattern results, which is the point: the correction surfaces next to the pattern it corrects, before the mistake is repeated.

Keep right concrete. A lesson whose correction reads "remember to use the repo" is worthless. One containing the five lines that were actually correct is not.

Lessons as training data

flutter-agent export-dataset lessons.jsonl

Converts every lesson to an instruction/response triple (system / user / assistant). This is the deferred path to fine-tuning a local model on your style — worth revisiting at a few hundred real samples, not before.

On fine-tuning, honestly

On a 6 GB laptop GPU, QLoRA on long Dart files is slow and the payoff is modest: a fine-tune bakes in style but not correctness, and it will still invent APIs. Retrieval plus the rule engine gets you most of the value at a fraction of the cost. The dataset is the real asset; keep collecting it and decide later.
